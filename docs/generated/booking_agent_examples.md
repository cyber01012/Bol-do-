# BolDo Booking Agent: Firestore Models, Session Updates, and Mock Trace Logs

This reference document contains the exact structured models, orchestration updates, and trace logs generated by the Booking Agent under various happy and failure paths.

---

## 1. Firestore Collection Examples

### A. `/providers` Collection
Describes a registered home service provider in BolDo.
```json
{

  "name": "Ali AC Repair",
  "service_type": "ac_technician",

  "is_available": true,
  "completed_jobs": 142,
  "location": {
    "latitude": 33.6844,
    "longitude": 73.0479
  }
}
```

## 2. Orchestration Session State Transitions

The pipeline moves incrementally through agent milestones:

1. **Discovery Stage Completed:**
   - Completed: `{"IntentAgent": true, "DiscoveryAgent": true, "RankingAgent": true}`
   - Status: `"success"`
2. **Pricing Stage Completed:**
   - Completed: `{"IntentAgent": true, "DiscoveryAgent": true, "RankingAgent": true, "PricingAgent": true}`
   - Status: `"success"`
3. **Booking Stage Completed (Booking Agent Execution):**
   - Completed: `{"IntentAgent": true, "DiscoveryAgent": true, "RankingAgent": true, "PricingAgent": true, "BookingAgent": true}`
   - Status: `"success"` (or `"failed_degraded"` if session is missing or pricing clamped to 500 PKR baseline).

## 3. Mock Trace Log Examples

### Trace Log: Double Booking Conflict Blocked
Written when provider has an overlapping booking within a +/- 2-hour slot buffer window.
```json
{
  "trace_id": "trace_book_1715800020_987",
  "session_id": "sess_conflict_444",
  "request_id": "req_conflict_555",
  "current_agent": "BookingAgent",
  "next_agent": "NotificationAgent",
  "orchestration_status": "failed",
  "timestamp": "2026-05-19T01:58:12.000Z",
  "inputs": {
    "provider_id": "prov_ali",
    "requested_time": "2026-05-19T15:00:00.000Z",
    "total_price": 1450.0
  },
  "decision": "Booking rejected: provider_double_booked.",
  "confidence": 1.0,
  "reasoning_breakdown": {
    "idempotency": "clear",
    "provider_availability": "active",
    "slot_simulation": "blocked_conflict",

```
